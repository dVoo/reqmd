checkVersionPins compares each downstream requirement's `~N` version pin
on a trace reference against the upstream requirement's `version`.
Findings:
- outdated — upstream version V > pinned N. Downstream must be re-verified.
- predated — upstream version V < pinned N. Downstream claims a version
that does not exist on the upstream; data integrity issue.

Both emit ERROR by default. Outdated findings carry
Code="version-pin" + Direction="outdated" and can be demoted to WARNING
by the cmd layer when --relaxed-versions is set. Predated stays ERROR.

Rules:
- Skip if the target is external (versions are out of our control).
- Skip if the upstream has no `version` (Version == 0): we have no
ground truth to compare against, so a pin to an unversioned upstream
is harmless. The pin is still recorded for inspection.
- A pin of 0 against a versioned upstream is reported as outdated:
the user wrote "~0" and the upstream has since been bumped.

SubgraphFromSeeds computes the bounded subgraph for scoped-check
mode. Given a list of seed requirement IDs and a lightweight index
of every requirement in the spec tree, it returns the set of doc
directories and req IDs that are within one hop of the seeds.

The subgraph is:
- target docs — directories containing any seed req
- direct upstreams — reqs referenced (via `trace`) by any seed
- direct downstreams — reqs whose `trace` list includes any seed

All edges come from the lightweight index; the function is pure
(no I/O, no global state, no side effects). A 1-hop bound is
intentional: a 2-hop expansion could surprise users who only asked
for a single req. Callers that need a wider scope should re-run
the function with the new frontier as additional seeds.

If a seed ID is not found in the lightweight index, it is reported
in SubgraphSelection.MissingSeedIDs. The other seeds are expanded
as normal; the function does not return an error in that case so
the CLI can show a "did you mean" hint and continue.
